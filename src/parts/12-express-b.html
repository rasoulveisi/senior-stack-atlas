Interview answer

Why are prepare: false and fetch_types: false set in src/db/client.ts?

1. prepare: false (Disabling Named Prepared Statements): Connection poolers like Cloudflare Hyperdrive and PgBouncer run in Transaction Pooling Mode. Transaction 1 might run on Postgres backend connection #42, while Transaction 2 runs on Postgres backend connection #19. Named prepared statements in Postgres are scoped to a specific backend TCP connection. Suppose postgres.js prepares statement s1 on connection #42 and later executes s1 on connection #19. Postgres crashes with ERROR: prepared statement "s1" does not exist. Setting prepare: false uses simple/unnamed protocol execution so transaction pooling works seamlessly.

2. fetch_types: false (Cold-Start Introspection): On connect, postgres.js normally runs SELECT oid, typname FROM pg_type... to discover custom Postgres types before your first query. In a serverless Worker, that extra query doubles your database round-trips on initial connection. Disabling fetch_types cuts cold-start DB latency in half.

1.9 Error Middleware · RFC 7807 · Log Noise Control

Central error handling

Express identifies an error handler by checking fn.length === 4 at runtime. Every failure exits through one RFC 7807 Problem Details contract.

Real-world picture

Every hospital department uses the same incident form. Whether an issue happens in reception, the lab, or pharmacy, any doctor can read any report in seconds.

The fn.length === 4 runtime gotcha

In Express, an error-handling middleware is identified by having exactly 4 arguments: (error, req, res, next).

Trap · Express Checks fn.length === 4

Omitting _next makes fn.length === 3 and silently skips your error handler

Even if you don't call next inside your error handler, you must include _next in (error, req, res, _next). If you write (error, req, res), fn.length is 3, so Express treats it as a normal middleware and skips it when an error occurs.

3 arguments: (error, req, res)

JavaScript function fn.length is 3. Express registers it as a normal request middleware.

→ skipped completely when next(err) is called

4 arguments: (error, req, res, _next)

JavaScript function fn.length is 4. void _next; satisfies the linter while keeping the 4th parameter.

→ catches every thrown error across the app

RFC 7807 / RFC 9457 (application/problem+json)

In src/middleware/error.ts, PhysioCoach AI replaces ad-hoc error payloads with RFC 7807 Problem Details for HTTP APIs.

Inconsistent Route Error Shapes

One route returns { error: "bad" } while another returns { msg: "failed", code: 12 }.

→ frontend needs custom error parsing per endpoint

One RFC 7807 Contract

Every error returns Content-Type: application/problem+json with type, title, detail, instance, traceId, and auditLogId.

export const errorHandler: ErrorRequestHandler = (error: unknown, req, res, _next) => {
  void _next;
  const candidate: HttpError =
    error instanceof Error ? error : new Error('Unexpected API error.');
  const status = resolveStatusCode(error, candidate);
  const traceId = req.traceId || crypto.randomUUID();
  const auditLogId = candidate.auditLogId || req.auditLogId || null;

  if (status >= 500) {
    console.error('request.failed', { traceId, auditLogId, error: candidate.message });
  }

  res
    .status(status)
    .type('application/problem+json')
    .json({
      type: `https://physiocoach.devbench.ir/problems/${status}`,
      title: STATUS_TITLES[status] || 'Request Failed',
      detail: candidate.message || 'Unexpected API error.',
      instance: req.originalUrl,
      traceId,
      auditLogId,
      ...(error instanceof ZodError ? { errors: error.issues } : {}),
    });
};

function getClientKey(c: ExpressRouteContext): string {
  const cfConnectingIp = c.req.header('cf-connecting-ip');
  if (cfConnectingIp) {
    return cfConnectingIp;
  }

  const forwardedFor = c.req.header('x-forwarded-for');
  if (forwardedFor) {
    return forwardedFor.split(',')[0]?.trim() || 'unknown';
  }

  const realIp = c.req.header('x-real-ip');
  return realIp?.trim() || 'unknown';
}

1.11 Ephemeral Port 0 · Fetch Bridge · End-to-End Pipeline

Pass port 0 to server.listen(0, '127.0.0.1') so the OS kernel assigns a free ephemeral loopback port to every concurrent test.

Hardcoding port 8787 is a hotel where 50 guests all fight over room 8787. Passing port 0 lets the front desk hand every guest any free room and take the key back at checkout.

Why traditional API tests fail

Most teams fall into one of two traps when testing Express APIs: mocking everything or hardcoding a single port.

Option A (Mock everything): Tests stay green while SQL queries or middleware order are broken.
Option B (Fixed port localhost:8787): Parallel test files crash immediately.

Ephemeral Port 0 + .fetch() Bridge

server.listen(0, '127.0.0.1') asks the macOS/Linux kernel for any unused loopback port right now. It runs a real HTTP request and closes the server in finally.

Node.js & Express core (1–5)

Interview answer · Q1

1. Is Node.js single-threaded?

Your JavaScript code runs on a single thread (the V8 Event Loop). A heavy synchronous for loop or JSON.parse blocks all concurrent users.

The C++ runtime (libuv) and OS kernel are multi-threaded and async. libuv uses a background thread pool (default 4 threads) for file I/O, DNS, and crypto (PBKDF2). It delegates network sockets (http, PostgreSQL TCP) to OS kernel async APIs (epoll on Linux, kqueue on macOS).

V8 Event Loop (1 thread)

Runs JS callbacks. Blocked by sync loops or huge JSON.parse.

libuv Pool (4 threads)

Offloads file I/O, DNS lookups, and PBKDF2 crypto.

OS Kernel Async

epoll (Linux) & kqueue (macOS) multiplex HTTP & Postgres TCP sockets.

Interview answer · Q2

2. What is the difference between app.use('/api', fn) and app.get('/api', fn)?

app.use matches any HTTP method and matches by path prefix (/api, /api/users, /api/v1/health), stripping /api from req.url inside fn.

app.get matches only GET requests and requires an exact path match (/api only).

app.use('/api', fn)

Any method · Prefix match (/api/*) · Strips /api from req.url

app.get('/api', fn)

GET only · Exact match (/api only)

Interview answer · Q3

3. How does Express know a middleware is an error handler?

By inspecting fn.length === 4 ((err, req, res, next)). If you omit the 4th parameter next, Express treats it as a regular 3-argument middleware and will never call it on error.

Interview answer · Q4

4. What happens if an error is thrown after res.write() has already started streaming a response?

Once HTTP headers and initial body bytes are flushed to the TCP socket, you cannot change the HTTP status code to 500. Express's default fallback checks res.headersSent and closes the socket connection so the client detects an incomplete transfer.

Interview answer · Q5

5. What is backpressure in Node.js HTTP servers?

Sometimes a fast server reads a large file or DB cursor faster than a slow mobile client can download it. Memory buffers then fill up and crash the server. Using stream.pipe() or pipeline() pauses reading when the socket write buffer is full (write() returns false). It resumes automatically on the 'drain' event.

Fast source read → write() returns false → Pause reading → 'drain' event → Resume stream

Security & authentication (6–9)

Interview answer · Q6

6. Why store a SHA-256 hash of a Refresh Token instead of PBKDF2/bcrypt?

Passwords have low entropy: Humans pick weak passwords, so they need a slow hash (PBKDF2/Argon2) to stop offline brute-forcing.

Refresh tokens have high entropy: They are 32 bytes (256 bits) of cryptographic random data (crypto.getRandomValues). With 2^256 possibilities, they are mathematically impossible to brute-force. A fast cryptographic hash like SHA-256 protects the token against database leaks without wasting CPU time on every token refresh.

Human Password · Low Entropy

Vulnerable to dictionary attacks → requires slow PBKDF2 (50,000 iterations) or Argon2.

32-Byte Token · 2^256 Possibilities

Impossible to brute-force → fast SHA-256 hash protects DB leaks with zero CPU waste.

Interview answer · Q7

7. How do you defend against Refresh Token theft if you don't store sessions on the server?

You can't—which is why pure stateless refresh tokens are an anti-pattern. You must store session metadata (auth_sessions) and track token rotation (auth_refresh_token_history). If a previously rotated refresh token is presented again, you immediately revoke the entire session family.

Interview answer · Q8

8. How do you prevent timing attacks during login?

First, compare password hashes using a constant-time XOR loop (timingSafeEqual). Second, if the email does not exist in the database, verify the incoming password against DUMMY_PASSWORD_HASH. That way, "user not found" takes the same ~40 ms of PBKDF2 CPU work as "wrong password".

Interview answer · Q9

9. Where should tokens be stored on the client?

Option 1 is HttpOnly; Secure; SameSite=Lax cookies, which are immune to XSS but require CSRF protection on mutations. Option 2 is in-memory access tokens paired with rotated refresh tokens, strict Content Security Policy, zero XSS vectors, and server-side reuse detection.

Databases & transactions (10–12)

Interview answer · Q10

10. What is the N+1 query problem and how do you avoid it in Drizzle?

You fetch 20 workout sessions (1 query) and then run a SELECT in a for loop for each session (20 queries). Fix it by fetching all related exercises in one query with inArray(exerciseLogs.workoutSessionId, sessionIds) or a SQL JOIN. Then group the rows in memory with a Map.

Interview answer · Q11

11. How do you prevent race conditions when two requests try to update the same row at the same time?

Use Optimistic Concurrency Control (Compare-And-Swap) in a single atomic UPDATE ... WHERE id = $1 AND refresh_token_hash = $2 RETURNING id. Alternatively, use Pessimistic Locking with SELECT ... FOR UPDATE inside a transaction.

Interview answer · Q12

12. Why must prepare: false be set when using PgBouncer or Cloudflare Hyperdrive in transaction mode?

Transaction-mode poolers reassign Postgres backend connections after every transaction. Named prepared statements live on one specific backend connection. The next query can hit a different backend that does not have that prepared statement.

System design, observability & operations (13–20)

Interview answer · Q13

13. How do you implement Graceful Shutdown in a containerized Express server?

Listen for SIGTERM from Kubernetes/Docker, then execute four ordered steps:

1. Stop new traffic

Call server.close() to stop accepting new connections.

2. Drain in-flight

Let active HTTP requests finish (with a hard timeout, e.g., 15 seconds).

3. Close DB pool

Close the PostgreSQL connection pool (await sql.end()).

4. Exit cleanly

Call process.exit(0).

Interview answer · Q14

14. What is Idempotency and why does POST /workout-plans/generate use an inputHash?

An operation is idempotent if calling it multiple times has the same effect as calling it once. By hashing the user's profile and assessment inputs (buildPlanInputHash), we can detect duplicate requests, reuse validated context, and correlate audit logs.

Interview answer · Q17

17. How do you handle slow third-party APIs (like LLMs) in Express without taking down your server?

1. Always pass an AbortSignal.timeout(timeoutMs) to fetch() so hung sockets never leak memory.

2. Configure ordered fallback models (primaryModel → fallbackModels).

3. Validate the third-party response with Zod before touching your database.

Interview answer · Q18

18. Why should /api/v1/health run SELECT 1 against the database?

A shallow health check that returns { ok: true } only proves the process is alive. It stays green even when database credentials break or the connection pool deadlocks. Running SELECT 1 and measuring responseTimeMs verifies true readiness (200 OK vs 503 Service Unavailable).

Interview answer · Q19

19. What is Prototype Pollution in Express and how do we prevent it?

If an attacker sends JSON like {"__proto__": {"isAdmin": true}} and your code recursively merges objects without checking keys, they can pollute Object.prototype. Validating every payload through strict Zod schemas (z.object({...}).strict()) strips or rejects __proto__ and constructor keys immediately.
