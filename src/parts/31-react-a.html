3.1 Functions · Snapshots · Pure Render · Keys

Rendering and state

A React component is not a living class instance. It is a pure function call that turns current props and state into UI.

The core formula

UI = f(props, state)

Every time state changes, React calls your function again from top to bottom.

Real-world picture

A React component is a photo booth. It prints a brand-new photo on each change instead of taking a pen to edit the old photo.

A function call, not a class instance

Local variables declared with const or let are created fresh on every render. Event handlers close over (capture) the props and state from that specific render.

Angular habit: Class instance

Angular calls new MyComponent() once, mutates this.someProperty over time, and checks the template when signals or zone events fire.

→ one mutable object lives for the whole lifetime

React way: Function snapshot

React runs your function again on every state change. Local variables are fresh and disappear when the function returns.

→ handlers capture that render's exact values

State is immutable and compared with Object.is

React checks whether state changed by comparing the old and new references with Object.is(oldState, newState).

Trap · Angular habit that breaks

toasts.push(newItem); setToasts(toasts)

The array reference did not change, so Object.is(oldArray, newArray) === true. React thinks nothing changed and skips re-rendering.

const [toasts, setToasts] = useState<ToastItem[]>([]);

const toast = useCallback<ShowToast>((message, tone = "success") => {
  const id = nextId.current++;
  setToasts((current) => [...current, { id, message, tone }]);
}, []);
  • 1[...current, { id, message, tone }] allocates a new array so Object.is sees a new reference.
  • 2current => ... reads the latest queued array instead of a stale closure.

Key idea

When two events fire in the same tick, setToasts(current => ...) guarantees the second update appends to the first update's array.

Derived values: compute during render

When a value comes from props or state, calculate it right inside the function body. Do not put it in useState or useEffect.

// Derived value: computed while rendering, from props. Not state, not an Effect.
const hasFilters = Boolean(search.q || search.status || search.assignee);
  • 1hasFilters runs on every render and can never go out of sync with search.

Angular habit: computed()

In Angular, the class instance runs once, so you wrap derived state in computed(() => ...) to track signal changes.

React way: Plain const

Your component function already runs on every render. A plain const variable is fast and needs no wrapper.

Key idea · React Compiler

Next Issue Tracker enables reactCompiler: true in next.config.ts (docs/adr/0003-react-compiler.md). At build time, the compiler caches derived values and JSX nodes automatically, without manual useMemo, useCallback, or React.memo.

The pure render rule

React and the React Compiler can call your component multiple times or cache its output. Rendering must stay pure.

Don't mutate outside

Never change variables outside the component function while rendering.

Don't call impure APIs in render

Never call Date.now(), new Date(), or Math.random() during render or inside a state reducer.

Do impure work in handlers

Event handlers like submit are not render—they can call new Date() and pass the value in.

const [visible, addOptimistic] = useOptimistic<CommentView[], OptimisticComment>(
  comments,
  (current, { body, at }) => [
    ...current,
    {
      id: `pending-${current.length}`,
      body,
      author: { id: "me", name: currentUserName },
      createdAt: at, // Uses `at` passed in, NOT `new Date()` inside the reducer!
      updatedAt: at,
      viewerCan: { edit: false, delete: false },
      pending: true,
    },
  ],
);

function submit(formData: FormData) {
  const body = String(formData.get("body") ?? "").trim();
  if (body) addOptimistic({ body, at: new Date() });
  return dispatch(formData);
}
  • 1submit() is an event handler, so creating new Date() there is safe.
  • 2The useOptimistic reducer runs during render and stays pure by reading at.

Syncing state when props change: key vs render-time setState

Instead of Angular's ngOnChanges, React gives you two patterns: change key to reset the whole component, or call setState during render to adjust specific fields.

Angular habit: ngOnChanges

Wait for an @Input() lifecycle hook and manually overwrite internal fields on the existing class instance.

React way: key or render guard

Pass a new key to remount a clean instance, or update state inside an if (prop !== seenProp) guard during render.

Senior interview questions

Interview answer · Q1

Why is copying props to state inside useEffect an anti-pattern, and what are the three right ways to handle prop-derived data?

Why it hurts: Calling setState(prop) inside useEffect makes React finish a full render and paint stale state first. It then immediately triggers a second render pass.

1. Compute during render: If the value comes from props or state, calculate it as a plain variable during render (like hasFilters in IssueFilters).

2. Reset all state with key: Pass a new key when an ID or version changes and you want a clean slate. IssueForm uses key={issue.updatedAt.toISOString()}.

3. Adjust specific state during render: To update only some fields while keeping focus in SearchBox, keep the component mounted. Call setState during render inside if (prop !== prevProp).

Interview answer · Q2

With React Compiler enabled, do I still need to care about immutability or pure rendering?

Yes, even more than before. React Compiler automatically memoizes values and JSX blocks using reference equality (Object.is) and assumes your render function has no side effects.

Never mutate an array in place or call impure functions like new Date() during render. Otherwise, the compiler may skip re-computing a block and leave stale UI on screen.

3.2 useEffect · useEffectEvent · Refs · Hydration

Effects and external systems

An Effect is only for synchronizing with an external system—a DOM listener, timer, WebSocket, or non-React widget.

Real-world picture

useEffect is a travel plug adapter. You only need it at the border between your device and a foreign wall socket.

The golden rule of useEffect

If no external system is involved, you do not need useEffect.

Angular habit: effect() / ngOnInit

Using effect() or ngOnInit to react to state changes or compute derived component fields.

React way: Border sync only

Reserve useEffect strictly for browser DOM listeners, setTimeout/setInterval, WebSockets, or non-React widgets.

Decision flow · Do I need useEffect?

01 · check

Is there an external system?

DOM listener, timer, WebSocket, or non-React widget?

02 · if no

Stay in React

Compute in render (const) or run in an event handler.

03 · if yes

Use useEffect + cleanup

Subscribe on setup and undo it in the returned cleanup function.

Subscribing to DOM events with useEffectEvent

Callers pass an inline arrow function useHotkey("/", (e) => { ... }) that creates a new function reference on every render. useEffectEvent (React 19.2+) reads the latest handler without re-subscribing the DOM listener.

export function useHotkey(
  key: string,
  handler: (event: KeyboardEvent) => void,
) {
  const onKey = useEffectEvent(handler);

  useEffect(() => {
    function listener(event: KeyboardEvent) {
      if (event.key !== key || event.metaKey || event.ctrlKey || event.altKey)
        return;
      if (isTyping(event.target)) return;
      onKey(event);
    }
    document.addEventListener("keydown", listener);
    return () => document.removeEventListener("keydown", listener);
  }, [key]);
}
  • 1useEffectEvent(handler) always calls the latest handler while keeping handler out of the [key] dependency array.
  • 2Returning () => document.removeEventListener(...) removes the listener on unmount or when key changes.
  1. 1

    Setup runs on mount

    React calls document.addEventListener("keydown", listener).

  2. 2

    Strict Mode cleanup check (development only)

    React simulates an unmount right away and calls removeEventListener to expose missing cleanups.

  3. 3

    Setup runs a second time

    Verified in use-hotkey.test.tsx: only one listener stays registered after setup → cleanup → setup.

The latest-ref pattern for timers

When a setTimeout starts inside an event handler instead of inside useEffect, store the latest callback in a useRef box.

export function useDebouncedCallback<Args extends unknown[]>(
  fn: (...args: Args) => void,
  delayMs: number,
) {
  const latest = useRef(fn);
  const timer = useRef<ReturnType<typeof setTimeout> | undefined>(undefined);

  useEffect(() => {
    latest.current = fn;
  });

  useEffect(() => () => clearTimeout(timer.current), []);

  return useCallback(
    (...args: Args) => {
      clearTimeout(timer.current);
      timer.current = setTimeout(() => latest.current(...args), delayMs);
    },
    [delayMs],
  );
}
  • 1latest.current = fn updates inside an Effect after each commit.
  • 2When the timer fires after delayMs (for example 300 ms), it calls latest.current(...args) with fresh props and state.

Why useRef?

{ current: value } is a mutable box that persists across renders without triggering a re-render when .current changes.

Why not useEffectEvent?

Effect Events can only be called from inside useEffect. Here, the timer starts inside a caller event handler (onChange).

Why not write latest.current in render?

Concurrent React can start a render, abandon it, or render out of order. Mutating a ref during render breaks purity.

Hydration-safe browser values with useSyncExternalStore

The server formats dates in UTC while the browser uses the user's timezone (for example +04:00). Calling date.toLocaleString() directly in render gives 14:00 UTC on the server and 18:00 in the browser, which is a React hydration mismatch. useSyncExternalStore keeps the server HTML and initial hydration pass identical before switching to local time.

const subscribe = () => () => {};

export function LocalTime({ date }: { date: Date }) {
  const text = useSyncExternalStore(
    subscribe,
    () => formatLocalDateTime(date), // 2nd arg: Client snapshot (after hydration)
    () => formatDateTime(date),      // 3rd arg: Server & hydration snapshot (UTC)
  );
  return <time dateTime={date.toISOString()}>{text}</time>;
}
  • 1The 3rd argument (formatDateTime) runs on the server and during the initial client hydration pass.
  • 2Right after hydration completes, React switches to the 2nd argument (formatLocalDateTime).

Old useState("") + useEffect

Renders an empty string "" on the server, leaving blank timestamps in SSR HTML and causing a layout shift after load.

useSyncExternalStore

Renders a real UTC timestamp in SSR HTML, hydrates with zero mismatch, and upgrades in place to the local timezone.

Senior interview questions

Interview answer · Q1

In development, my useEffect runs twice when the component mounts. Is that a bug, and how should I handle it?

It is intentional behavior from React <StrictMode>. React simulates unmounting and remounting every component in development (setup → cleanup → setup) to verify that your cleanup function undoes setup.

Never block the second run with a useRef(false) guard. Instead, write a proper cleanup function such as removeEventListener, clearTimeout, or abortController.abort().

Interview answer · Q2

How do you avoid hydration mismatches when rendering browser-only data like window.innerWidth, localStorage, or user timezone?

Use useSyncExternalStore(subscribe, getClientSnapshot, getServerSnapshot).

Provide a deterministic server fallback in getServerSnapshot (used during SSR and initial hydration) and read the browser API in getClientSnapshot right after hydration completes.

3.3 Server & Client · Donut Pattern · Context · useId

Composition and the donut pattern

A Client Component can wrap Server Components passed as children without adding them to the browser bundle.

Real-world picture

A Client Component is a picture frame with a dimmer switch. A Server Component is a printed photo slid inside the frame.

The server/client boundary and the donut pattern

In Next.js App Router, every component is a Server Component by default unless the file starts with "use client". Server Components run only on the server, can await database queries directly, and add 0 KB JS to the browser bundle.

Rule 1 · Imports become client code

Any module directly imported by a "use client" file is bundled into client JavaScript.

Rule 2 · The Donut escape hatch

A "use client" component can accept Server Components as children (or any JSX prop) while keeping them on the server.

React 19 Context design: keep changing state out of broad contexts

ToastContext provides only the stable toast function, never the changing toasts array.

const ToastContext = createContext<ShowToast | null>(null);

export function useToast(): ShowToast {
  const toast = use(ToastContext);
  if (!toast) throw new Error("useToast must be used inside <ToastProvider>.");
  return toast;
}
  • 1ToastContext carries ShowToast (a stable callback), not ToastItem[].
  • 2use(ToastContext) reads the context using React 19's use() API.

Older React syntax

Render <ToastContext.Provider value={toast}> and read with useContext(ToastContext), which cannot run inside if blocks.

React 19 syntax

Render <ToastContext value={toast}> directly and read with use(ToastContext), which can be called conditionally after early returns or inside if blocks.

useId and why fixed DOM IDs break in Next.js 16

Next.js 16 uses React <Activity> to keep previous routes hidden in the DOM. If both /issues/new and /issues/1/edit render id="title", clicking the label on Edit focuses the hidden New Issue input.

export function useFieldId() {
  const base = useId();
  return (name: string) => `${base}-${name}`;
}
  • 1useId() generates a deterministic ID shared between Server and Client hydration.
  • 2Every mounted form gets its own namespace (for example ${base}-title).

Senior interview questions

Interview answer · Q1

Can a Client Component render a Server Component? Explain how the module graph works.

Cannot import directly: A Client Component cannot import a Server Component. "use client" marks the boundary where all imported files are bundled for the browser.

Can render via props: A parent Server Component can pass a Server Component into a Client Component via children or another JSX prop. React renders the Server Component on the server into a serialized RSC payload (virtual DOM description) and slots it into the Client Component.

Interview answer · Q2

How do you prevent unnecessary re-renders when using React Context for global UI features like Toasts or Modals?

Separate the command/dispatch context from the state display.

Put only stable functions (like showToast) in the broad context so components that trigger toasts never re-render when toasts change. Only the <ToastRegion> component holds or reads the changing array of active toasts.

3.4 useTransition · useOptimistic · useActionState · useFormStatus

React 19 concurrent and form APIs

React 19 replaces manual isLoading and rollback boilerplate with four coordinated hooks for transitions, optimistic UI, and forms.

Real-world picture

A waiter writes "coming soon" on your table card right away, and wipes it clean if the kitchen says no.

Four coordinated React 19 hooks

Three hooks come from react and one comes from react-dom.

Angular / older React habit

Manually managing isLoading, error, and a saved prevValue variable with try / catch rollback code on every mutation.

React 19 way

Coordinate async mutations with useTransition, useOptimistic, useActionState, and useFormStatus.

useTransition · from react

Run a state update or async action in the background without blocking user input; tracks pending. Examples: StatusControl, SearchBox.

useOptimistic · from react

Immediately show the expected new UI state while an async transition or action is in flight; auto-reverts when it ends. Examples: StatusControl, CommentThread.

useActionState · from react

Wire a <form> to (prevState, formData) => nextState, tracking the latest FormState and isPending. Examples: IssueForm, CommentThread.

useFormStatus · from react-dom

Read { pending, data } of the parent <form> from inside a child component. Example: SubmitButton.

How useTransition and useOptimistic work together

StatusControl updates the dropdown immediately and lets React handle both seamless server confirmation and automatic failure rollback.

6-step StatusControl lifecycle · Success vs failure branch

01

Select

User picks "in_progress".

02

Transition

startTransition sets pending = true.

03

Optimistic UI

setOptimisticStatus shows it with zero delay.

04

Server Action

changeStatusAction + updateTag.

05 · if ok

Streams new prop

Server sends status="in_progress", no flicker.

or

05 · if error

Auto-rollback

Transition ends; React reverts to server status.

const [optimisticStatus, setOptimisticStatus] = useOptimistic(status);
const [pending, startTransition] = useTransition();

function onChange(next: IssueStatus) {
  startTransition(async () => {
    setOptimisticStatus(next);
    const result = await changeStatusAction(issueId, next);
    if (result.ok) toast(`Status changed to ${STATUS_LABELS[next]}.`);
    else toast(result.message, "error");
  });
}
  • 1setOptimisticStatus(next) switches the displayed status before the network request starts.
  • 2If result.ok is false, you only show an error toast—React drops the optimistic overlay automatically when the transition settles.

Why SubmitButton must be a separate child component

useFormStatus() works like reading Context from the nearest ancestor <form>.

Trap

useFormStatus() in the same component that renders <form> is always false

A hook called above <form> has no parent form to read from. Always call useFormStatus() inside a child component rendered inside <form>...</form>.

export function SubmitButton({ children, pendingLabel, ...props }) {
  const { pending } = useFormStatus();
  return (
    <Button type="submit" disabled={pending || props.disabled} aria-disabled={pending} {...props}>
      {pending && pendingLabel ? pendingLabel : children}
    </Button>
  );
}
  • 1useFormStatus() returns { pending } from the enclosing <form>.
  • 2While the form action is running, the button disables itself and swaps in pendingLabel.

Senior interview questions

Interview answer · Q1

What is the difference between a normal state update and a state update wrapped in startTransition?

Urgent vs non-urgent: Normal state updates (like typing into an <input>) are urgent and synchronous—they block the UI until rendered.

Interruptible transitions: Wrapping an update (or a Next.js router navigation) in startTransition marks it as non-urgent and interruptible. While a transition is pending, React keeps the current UI interactive on screen instead of showing a blank fallback. If the user types again, React interrupts the stale render.

Interview answer · Q2

How does useOptimistic handle rollbacks when a server mutation fails?

useOptimistic(passthroughState) never permanently mutates state.

The temporary optimistic value exists only while an async Action or startTransition is actively pending. The moment the transition settles, React discards the optimistic overlay and falls back to the authoritative passthroughState prop from the server.
