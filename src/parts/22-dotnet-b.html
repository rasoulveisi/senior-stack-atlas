2.9 60-Second Answers · EF Core · Runtime · HTTP

Interview cheat sheet

Eight core .NET backend topics you must explain clearly in 60 seconds each.

Real-world picture

A 60-second interview answer is an emergency briefing. Name the runtime mechanism first, call out the production trap second, and state the fix third.

Interview answer · 1 of 8

1. IQueryable<T> vs. IEnumerable<T>

IQueryable<T> builds an Expression Tree (Expression<Func<T, bool>>) that EF Core translates into SQL to run on the database server.

IEnumerable<T> runs delegates (Func<T, bool>) in C# memory. Converting to IEnumerable before filtering pulls the entire table over the network into RAM first.

Interview answer · 2 of 8

2. async / await under the hood

async does not spin up a new thread. The C# compiler rewrites your method into a state machine (IAsyncStateMachine).

While waiting for network or disk I/O (like Postgres or OpenRouter), the thread returns to the .NET Thread Pool to serve other HTTP requests. Always return Task or Task<T>.

  1. 1

    Start I/O and reach await

    IAsyncStateMachine records current local variables and registers a continuation.

  2. 2

    Thread returns to the .NET Thread Pool

    Zero thread blocked while Postgres or OpenRouter processes the request.

  3. 3

    I/O completes → state machine resumes

    A pool thread picks up the next state and completes the returned Task<T>.

Trap 1: .Result or .Wait()

Thread-pool starvation & deadlocks

Blocking a thread synchronously while waiting for an async task causes sync-over-async deadlocks and starves the thread pool.

Trap 2: async void

Exceptions crash the whole process

Callers cannot await async void or catch its exceptions. Always return Task or Task<T>.

Interview answer · 3 of 8

3. ValueTask<T> vs. Task<T>

Task<T> is a reference type that allocates on the heap unless cached. ValueTask<T> is a struct.

Use ValueTask<T> on hot paths where the result is usually available synchronously (such as hitting an in-memory cache 99% of the time). Never await a ValueTask<T> more than once.

Feature Task<T> ValueTask<T>
C# type Reference type (class) Value type (struct)
Sync completion cost Allocates on the heap (unless cached) Zero heap allocation
When to use Default for normal async I/O methods Hot paths that hit an in-memory cache ~99% of the time
Consumption rule Can be awaited multiple times Do not await more than once

Interview answer · 4 of 8

4. Garbage Collection (GC) & memory generations

.NET divides the managed heap into Gen 0, Gen 1, Gen 2, and the Large Object Heap (LOH). Gen 0 holds short-lived HTTP request DTOs, Gen 1 acts as a buffer, and Gen 2 holds long-lived Singletons. The LOH stores objects >= 85,000 bytes, such as huge arrays or giant strings.

Gen 0 collections are sub-millisecond, while LOH and Gen 2 collections are expensive. Avoid allocating huge strings or arrays repeatedly in loops; use ArrayPool<T>, Span<T>, or streaming instead.

Gen 0 · Short-lived HTTP DTOs · Sub-millisecond GC
Gen 1 · Buffer between Gen 0 and Gen 2
Gen 2 · Long-lived Singletons · Expensive collection
Large Object Heap (LOH) · Objects >= 85,000 bytes · Expensive collection
Zero-LOH tools: ArrayPool<T> Span<T> Streaming I/O

Interview answer · 5 of 8

5. Tracking vs. AsNoTracking() in EF Core

Default queries attach entities to the ChangeTracker so SaveChangesAsync() knows which columns changed.

For GET endpoints that only serialize to JSON, always add .AsNoTracking() to skip snapshot allocation.

Default tracked query on GET

Attaches every entity to ChangeTracker and allocates original-value snapshots in memory.

→ only needed before SaveChangesAsync()

.AsNoTracking() on GET

Skips ChangeTracker snapshot allocation and streams rows straight to JSON serialization.

→ lower memory and faster read endpoints

Interview answer · 6 of 8

6. The N+1 query problem

What happens: You load 50 Applications in 1 query and then loop over them to query each application's Analysis separately. That loop turns 1 query into 1 + 50 = 51 database round-trips.

The fix: Batch related rows in one query with WHERE application_id = ANY(...) (pageIds.Contains(a.ApplicationId) in ApplicationService.cs, lines 75–83). You can also use .Include(...) or a .Select(...) projection.

Interview answer · 7 of 8

7. Middleware order in Program.cs

Middleware runs as a Russian-doll pipeline (first in, last out).

UseExceptionHandler() must sit at the very top so it catches exceptions thrown by everything nested inside it: UseCors(), UseAuthentication(), UseAuthorization(), and your endpoints.

Interview answer · 8 of 8

8. RFC 7807 ProblemDetails

Standardize every error response. Instead of inventing custom { error: true, msg: "..." } shapes per endpoint, senior APIs register builder.Services.AddProblemDetails() and return Results.Problem(...).

Frontend interceptors like Angular's HttpInterceptorFn then rely on one predictable RFC 7807 JSON contract across the entire app.

  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.10",
  "title": "Concurrency conflict",
  "status": 409,
  "detail": "The record was modified by another user.",
  "instance": "/api/applications/42"
}
  • 1AddProblemDetails() and Results.Problem(...) emit the five standard RFC 7807 fields: type, title, status, detail, and instance.
  • 2Angular's HttpInterceptorFn parses one error shape across every route instead of guessing custom fields.
